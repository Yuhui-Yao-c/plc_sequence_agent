# 变更记录

## 12.0.0 — 入口一时序拆解交付格式（2026-11-17）

- 主表改为「时序拆解」，保留模板的 13 列，新增「描述来源」与末列「证据链」。按列号消费旧工作簿的程序需相应调整。工序文件名和两个命令入口沿用原约定。
- 每行按完整起止标签追溯跳变样本索引、采集 ID（Sysmac）、起始步时长、源码关系与 A/B 档依据。待处理或证据不足的行展示观测与具体缺口。
- 待料、堵料颜色采用可定位的源码步定义或有原文佐证的等待门控。普通等待仅标 1。保留空白定额和编号。
- 对声明 `MicroSeconds=True` 的原生记录，在计算停留时长前将微秒换算为毫秒。配置未声明该选项时沿用毫秒。
- 验收逐行核对转接片 174 对、顶盖焊 401 对、包 mylar 四次 Sysmac 采集 928 对的标签、时长、样本索引与证据链。两份原生记录的时长另从原始时间戳独立重算。转接片完成本轮 31 条 B 档判读；另两份用于核验制表与待处理状态。70 项回归通过。

## 11.0.0 — 根据工程 XML 配置汇川采样任务（2026-11-17）

- 入口二按任务调度、程序及例程调用、明确写入和匹配通道的关系选择一个采样任务。支持标准 PLCopen 和厂商扩展中的分离例程。每个任务记录去重通道及可回查的 XML 行号。多任务覆盖并列、跨资源、任务声明缺失和写入证据不足时报告 `needs_review`，保留变量清单。
- 将任务名、每 N 个周期采样的分频和运行时缓冲写入原生 `Record`。已知任务周期时，按 2 秒目标窗口计算缓冲。采样分频默认 1。移除 10.3.0 的 `--task-from-trace`，公共 CLI 变更按规则升级主版本。
- 用独立的工程 XML 生成并回读配置。转接片默认 `Task_Station`（8 ms、251 点），原实测用 `MainTask`（4 ms、501 点）。超声自动选到 `PrimaryTask1`（8 ms、251 点），顶盖焊选到 `MainTask`（16 ms、126 点），均与历史记录采样设置中的这三项一致。X-RAY 仅用 XML 得到 `Main`（4 ms、501 点）。
- 四个汇川工程的静态通道清单与 10.3.0 一致。顶盖焊实测的 42 个通道中 41 个可由显式引用匹配，另一个通道在所给 XML 中缺少完整显式引用。包 mylar 的 128 通道 Sysmac CSV 与 10.3.0 逐字节一致。68 项回归通过，已核验生成文件并确认 OpenCode 1.18.18 加载项目 Agent 和四项技能。现场客户端导入及在线采样仍需实机核验。

## 10.3.0 — 汇川 Trace 采样任务（2026-11-17）

- 入口二同时读取 PLCopen 资源和厂商扩展中的任务声明、周期、优先级、对象 ID 与程序实例。任务名按源码核对，状态记录选取依据、采样分频与可计算的名义采样间隔。事件任务或周期数据冲突时，名义间隔留空。
- 简写与完整 CLI 均支持 `--task-from-trace` 复用参考记录的 `TaskName`、`EveryNCycles`，也可按需指定 `--task-name`、`--every-n-cycles`。生成文件的通道来自当前 XML，采样数据为空。
- 转接片 XML 读出 10 个任务。按现场样例生成的 30 通道配置使用 `MainTask`，每周期一次，名义间隔 4 ms。指定 `Task_Station` 每两周期一次得到 16 ms。验证覆盖文件配置与实测时间戳，客户端导入和 PLC 在线采集需在现场核验。
- 64 项回归测试通过。转接片、顶盖焊、Sysmac 包 mylar 三个既有工序的默认配置（90、154、128 个通道）与 10.2.0 逐字节一致。

## 10.2.0 — 采集配置支持多模式并集（2026-11-11）

- 入口二支持 `源码 模式1 [模式2 ...] --trace-setup [-output 输出根目录]`，完整 CLI 可重复指定 `--pattern`。每个模式独立编译，混用完整名称、通配和 `re:` 正则；一次扫描取并集，重叠变量去重，保留自然排序。
- 保留单模式、`--regex`、大小写匹配、类型核验及输出子目录规则。状态文件新增 `patterns`，原 `pattern` 在单模式时仍为字符串，多模式时为 `null`。
- 多模式不替代功能块实例解析或缺失类型声明。入口一的 Trace 解析、状态对聚合和描述协议保持原实现；不同命令共享步号的上下文问题仍需独立适配。
- 56 项回归测试通过，覆盖模式并集、重叠去重、混合正则与通配、多维下标、大小写、独立模式校验、两种 CLI 形式及输出子目录。三个真实工序原有 90、154、128 个通道的单模式配置逐字节一致，OpenCode 主 Agent 与技能加载通过。
- 配对机 XML 的三个模式合并得到 46 个显式变量，与单独匹配的并集一致，无重复；34 个变量缺少成员类型声明，仍如实标记 `needs_review`，此数量不代表完整实例化后的全部步序。
