## 14.0.0 — 入口二按工位自动步确定采集范围（2026-11-18）

- 旧版自动模式将生产子流程和混用状态一起纳入采集。新版先确认本工程的工位步序接口，再逐通道核对生产例程、实例、成员和确切下标的声明。独立工位可使用不同接口；正式工位数组中执行局部动作的槽位可引用同一工位程序及声明地址内的真实同伴。内部执行、许可、数据记录和用途不明的候选保留在审计中。
- 从 Sysmac 与 PLCopen 导出提取声明原文及实际写步程序。对某变量的全部已提取迁移都受同例程中另一已选游标的具体步值约束时，检查对应的独立写入及实际调用实例。该候选默认转入复核。同工位正式槽位有可核验的同一数组及门控证据时允许保留。只有部分迁移存在握手条件时，不触发整通道复核。
- 自动模式的用途文件升级为 v2，旧用途文件需要从 XML 重新生成。`scope_results.json` 的 `admission` 记录每个用途判断的最终处理。单模式、多模式和两个入口的 CLI 用法沿用原格式。

- 从六份工程 XML 独立生成清单，发现时未读取现场通道表。包 Mylar 从 116 收敛为 60，截图所指的四组滚轮段和通信段变量均未进入配置；超声由 68 收敛为 46，同类型的 20 个动子移送和 2 个接驳段留在审计。另将供料权与取放记录故意提名为工位步，程序按其全部 4/4 与 2/2 个依赖写步将两者转入复核。
- 发现结束后用独立实测记录核对，包 Mylar、超声、转接片、顶盖焊的活跃通道分别保留 50/50、36/36、25/25、39/39。对应四份新配置为 60、46、56、48 个通道。包 Mylar 旧记录中的五个零跳变通道没有独立的受约束写步，仍在审计。X-RAY 的 26 个生产通道保留，配对机判定 3 个变量族的 36 个通道，其中 27 个缺失整数叶声明，记录待核并保留配置交付限制。
- 六份显式模式清单和五份可生成的配置与 13.1.0 逐字节一致。入口一重跑转接片，162 个状态对的采集清单、跳变、稳定段、通道、采样缺口和迁移复核文件逐字节一致。95 项回归通过。工程全量精确率及客户端实机导入仍需现场标注和验证。

## 11.0.0 — 根据工程 XML 配置汇川采样任务（2026-11-17）

- 入口二按任务调度、程序及例程调用、明确写入和匹配通道的关系选择一个采样任务。支持标准 PLCopen 和厂商扩展中的分离例程。每个任务记录去重通道及可回查的 XML 行号。多任务覆盖并列、跨资源、任务声明缺失和写入证据不足时报告 `needs_review`，保留变量清单。
- 将任务名、每 N 个周期采样的分频和运行时缓冲写入原生 `Record`。已知任务周期时，按 2 秒目标窗口计算缓冲。采样分频默认 1。移除 10.3.0 的 `--task-from-trace`，公共 CLI 变更按规则升级主版本。
- 用独立的工程 XML 生成并回读配置。转接片默认 `Task_Station`（8 ms、251 点），原实测用 `MainTask`（4 ms、501 点）。超声自动选到 `PrimaryTask1`（8 ms、251 点），顶盖焊选到 `MainTask`（16 ms、126 点），均与历史记录采样设置中的这三项一致。X-RAY 仅用 XML 得到 `Main`（4 ms、501 点）。
- 四个汇川工程的静态通道清单与 10.3.0 一致。顶盖焊实测的 42 个通道中 41 个可由显式引用匹配，另一个通道在所给 XML 中缺少完整显式引用。包 mylar 的 128 通道 Sysmac CSV 与 10.3.0 逐字节一致。68 项回归通过，已核验生成文件并确认 OpenCode 1.18.18 加载项目 Agent 和四项技能。现场客户端导入及在线采样仍需实机核验。
