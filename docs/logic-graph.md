# PLC 逻辑图谱的证据与数据结构

入口三从原始工程和实测记录建立索引，输出可离线打开的 HTML、同内容的压缩 JSON 和带 SHA-256 的运行清单。图谱使用完整地址与下标，覆盖已导出的网络以及解析器能识别的状态写点。查看器按变量、例程、信号分页；图形支持缩放，元件与端口保留 XML 位置。

| 视图 | 可核对的事实 |
| --- | --- |
| 步序与观测 | 连续采样中的相邻变化，发生次数、采集 ID、原始样本索引及记录内毫秒时间。多个采集、共同断档及单通道缺测沿用入口一的边界。 |
| 门控与源码网络 | 源码局部写点、原文、布尔层级、接线端口、静态候选路线和可能的其他写点。PLCopen 使用 body 内的 localId 和输出形参，Sysmac 使用单梯级输出端口，SMC2 使用 CLs/VLs 坐标连通关系。 |
| 信号读写 | 显式实际操作数、线圈和 ST 的赋值及读取位置。核对声明后区分全局与程序局部。同名来源可能多于一个。 |
| 工程与核验 | 跨变量条件读写及例程调用图、导出的 PLCopen 任务与挂载程序、能定位到定义的调用、原始接线及 ST 解析边界。 |

交互接线图按来源端口指向目标端口。常开、常闭触点显示不同符号；逻辑分支用 AND、OR、XOR 和 NOT 显示。数据实参、功能块控制输入和输出端口分别保留。对内部实现未导出的块，只能追到接口。相关格式与绘图依据见 [PLCopen XML](https://www.plcopen.org/standards/logic/iec-61131-10/) 和 [CODESYS 梯形图触点](https://content.helpme-codesys.com/en/CODESYS%20LD%20FBD/_cds_ld_element_contact.html)。

## 对照规则

- `direct` 表示存在起止值相符的源码写点。每个写点独立记录局部门控是否完全解析。扫描内的读写顺序、外部写入、实际选中哪条支路仍需单独证据。
- `path` 表示同一完整地址、同一写入作用域及实例绑定内的一条多步可达路径。每个可达的作用域给出一条最短示例，保留每段的全部写点。条件可在不同扫描中改变。
- `unresolved` 保留只有观测支持的变化。`source_only` 保留源码中有写点但本次没有观测到的状态对。SMC2 导出可能缺少变量声明及实例绑定；同名且作用域未核实的源地址单独列出。
- 直接写点的操作数有明确声明且也被记录时，CSV 取同一采集的同一行，原生 Trace 取同一采集内两端均唯一的相等时间戳。重复时间戳、缺测、同名局部量和相邻采样不能补值。条件读数只代表采样时的值。
- 未解析的语言、库块、动态下标和扫描内因果关系会限制能证明的范围。ST 附原文与解析范围；SMC2 网络定位使用工程条目、网络序号及网格坐标。

## 机器读取

`gzip.open(path, 'rt', encoding='utf-8')` 后用 JSON 读取。超出浏览器安全整数范围的步值及操作数以十进制字符串保存。协议名为 `plc.logic_graph.v1`。

| 字段 | 含义 |
| --- | --- |
| `channels[].pairs[]` | 起止值、relation、直接写点索引 sites、多步候选 paths；events 的每项为采集编号、记录内索引、记录内时间，以及可选的同采样操作数字典。 |
| `sites[]` | 原始门控文本及结构、作用域、行号、已绑定实例、局部完整度和对应的 net、source_node。缺少唯一位置时引用为 null。 |
| `nets[]` | scope、语言、网络、节点及 wires。每条线为来源节点 ID、来源引脚、目标 ID、目标引脚及连接种类。空引脚表示导出未命名，匿名输入可附第六项记录 XML 声明位置；同一 body 内的跨网络引用可跳转。 |
| `symbols[]`、`calls[]`、`tasks[]` | 作用域化的操作数读写位置、条件使用它的写点、可定位的调用定义和项目导出的任务。另见 `channel_dependencies`，箭头从被读取的步序变量指向写入目标。 |
| `wiring_issues`、`limits`、`trace_audit` | 源码引用及控制分析边界，采集分组、断档及无法唯一对时的读数。 |
