# Trace 采集配置

## 输入与范围

读取[主 Agent](../../agents/plc-sequence.md)入口二指定的工程及本轮产物。默认采集**工位自动步**。它的当前值能回答“这个工位或独立作业单元的自动周期进行到哪一阶段”。工位正式自动步数组还可有记录局部动作的槽位。同一工位可有多个并行周期，同一工程可有多种完全不同的步序接口。发现阶段只用原始源码。人工监控赋值、历史配置、实测 Trace 和人工表仅可在发现结束后用于独立验收。

## 自动发现

1. 执行 `python plc_cli.py "工程.xml" --trace-setup`，传递用户指定的任务和输出根目录。保存返回的 `out`，从该目录的 `workflow_status.json` 查看进度。遇到 `scope_review_pending` 时记录 `inventory_sha256`，继续第 2 步；遇到完成状态时直接验收。只有用户要求重新判定时才使用新根目录或显式归档重建。
2. 分批读取本轮 `scope_candidates.jsonl`。按 `family` 浏览工程内的所有候选，比较各自代表什么生产单元。比较声明中的实例、成员和精确下标注释，再沿调用回到实际工位，核对启动、运行、完成或下一轮进入的代码。需要时在 `step_variable_discovery.json` 查该变量的完整迁移、受控输出、门控和可写实参，再到原始 XML 相应位置核对。组名仅辅助阅读，每个成员须独立核实。
3. 为每个有独立作业周期的步序接口选一个有充分依据的实例。说明该接口的**业务边界**：谁拥有该周期，周期从哪项工艺任务开始、完成什么，如何和本工程中相近的局部执行过程区分。并行分支可以属于同一工位；应有其自身所承担作业的依据。只在一次命令或一个输送段内部轮转、为其他游标提供许可、交接、记录或数据交换的状态留在审计。多个部件共用上层运行门控时，检查各自下标表示独立工位还是同一装置的内部段位。用另一套结构拼写、标为自动、类型相同、由任务调度、能驱动物理输出或会循环，单项均不足以判定层级。反过来，经过功能块间接写入、同一游标兼做初始化，都可以有真实工位周期，须查看相应生产例程。
4. 确认工位的正式步序接口后，回查其在同一工位程序中实际推进的其他槽位。`station_slot` 用于这种有独立写步依据的生产槽位，记录 `interface_peer` 指向当轮已确认的 `station_auto` 通道。工位将某个槽位交给轴、解锁、扫码或交接例程写回时，该槽位仍反映工位对外可见的自动进度，即使它只负责单项动作。核实同一具体数组声明、工位程序和自动运行分支，不能仅凭相同类型或名字。只有初始化、手动维护、单次测试或在项目中从未推进的槽位分别排除。若整个数组本身就属于装置内部，各下标不能互相举证成为工位接口。

   对每个 `scope_required` 候选给出一种角色。`station_auto` 表示能证明本通道代表工位或独立作业单元的自动周期。`component_sequence` 用于已识别的内部执行步骤，`auxiliary` 用于数据、许可、记录、维护等其他用途，`uncertain` 保留无法确定的层级。源码未能区分工位与组件时填写具体缺口。对近似名字、同类型不同实例及共用多个模式的通道分别判断。
5. 在实际运行目录写入 `scope_results.json`。每个入选变量族在 `station_families` 内提供一个真实代表和边界说明。每个候选在 `decisions` 中恰有一项。两类采纳项均填写完整 `owner_scope`，引用该生产例程里本通道的迁移和本通道的全部声明编号（包括可用的精确下标注释）。声明缺少用途文本时，补充该例程内另一起始步的迁移、受控输出或实际可写绑定。槽位的 `interface_peer` 须与其共享已解析的声明地址和实际生产程序。即使声明有注释也要读代码确认其层级。依据引用局限于当前具体通道。示意结构如下，内容和编号均须用本工程证据替换。

   ```json
   {
     "inventory_sha256": "本轮指纹",
     "station_families": [{"example": "具体通道", "boundary": "该工位独立作业的开始、结束与内部过程的区别"}],
     "decisions": [
       {"name": "具体通道", "role": "station_auto", "owner_scope": "完整生产例程", "basis": ["d1", "t1", "e1"], "reason": "该实例如何推进此工位的自动作业"},
       {"name": "同工位另一槽位", "role": "station_slot", "interface_peer": "具体通道", "owner_scope": "该槽位的生产例程", "basis": ["d1", "t1", "t2"], "reason": "该槽位如何记录本工位的生产动作"},
       {"name": "另一候选", "role": "component_sequence", "basis": ["t1"], "reason": "该变量在上层作业中的局部用途"}
     ]
   }
   ```

6. 运行 `python plc_cli.py trace-setup --source "工程.xml" --out "本轮实际目录" --scope-results "本轮实际目录/scope_results.json"`，复用首轮任务与格式选项。程序重算证据并校验指纹、接口代表、逐实例归属和引用。对全部已提取写步都依赖同例程另一已选游标特定步值、且后者有独立写步的候选，程序记录 `admission=review` 及 `gated_by`。若已独立证明是正式工位槽位，且这些门控均来自同一声明数组与工位程序，可保留采集并记录门控。查最终 `admission=captured` 的数量和清单。报告排除的内部流程、数据以及仍待核的范围。若没有能核实的工位自动步，交付证据和缺口。

## 显式选择

用户提供完整变量名、通配或 `re:` 时，直接按[入口命令](../../agents/plc-sequence.md)运行。多个模式分别传入，取并集并按完整变量名去重。通配方括号按字面匹配。完整 CLI 可重复传 `--pattern`，或选择 `--regex`。报告显式可执行引用及动态下标。Sysmac 仅在手动模式下允许对缺失根声明使用已经工程核实的 `--default-type`。

## 验收

- 对照 `static_variables.txt`、配置通道数、任务以及 `workflow_status.json`。汇川沿用本工程任务名、写入覆盖、名义采样周期和缓冲点数，必要时依据 `task_note` 报告冲突。Sysmac 检查每个采纳通道的整数叶类型。
- PLCopen 存在任务表时，检查 `scheduled_writers` 的任务、调用链及实际写步行号。SMC2 导出若缺作用域或叶类型，自动模式保留网格证据并报告待核。
- 自动模式报告用途待核、只有引用的同族成员、未解析类型及源码解析限制。自动派生的选择器只代表本工程的集合回放；有额外命中时保留显式清单。经 FB 绑定得到的通道可能在源码中没有完整拼写。
- `done`、`done_with_review` 均应有配置，后者需披露待核范围。`needs_review` 说明未交付配置的具体原因。`scope_review_pending` 是中间状态。配置采样数为 0；工程师在对应客户端导入、检查容量及采样设置，并在现场采集。
