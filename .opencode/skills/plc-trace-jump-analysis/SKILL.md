# Trace 跳变与时长

## 触发

入口一读取实测记录时加载。

## 输入

| 入口 | 输入 | Python 模块 |
| --- | --- | --- |
| 一 | 源码和 TwinCAT Scope `.trace`、Sysmac 导出表或采集目录 | `plc_trace.trace.trace_to_pairs` |

原生 Trace XML 的 `TraceVariable` 包含 `Values`、`Timestamps`。配置声明 `MicroSeconds=True` 时按微秒读取并换算为毫秒，未声明时按毫秒读取。`StartTime` 提供绝对基准。

Sysmac 输入是 `.csv/.tsv/.txt`，也可用含这类表的目录。采样行含 `Index`、`RawTime` 及带整型后缀的变量列，例如 `Cell.Phase[0]:INT`。采集配置文件无采样行，应先导出现场实测记录。

## 执行

### 入口一的观测状态对

1. 目录顶层保留 `YYYYMMDDhhmmss_00001.csv` 等原名。按前缀识别采集，按卷号读取，核验同次采集的通道、设置、`StartRawTime` 和递增索引。重命名的文件仅在采集归属可以唯一确认时读取。索引缺口切断连续段，重复分卷与冲突按审计处理。
2. 每组独立识别相邻样本跳变和稳定段。非活动通道保留元数据，长空闲段作为周期边界候选。不同采集与断开的索引段之间不构造跳变。保留返回步 0 的观测对。
3. `RawTime` 为纳秒。精度不足时用同次采集的精确时间重建，或使用已知的 `--sample-interval-ms`。采样依据、估算次数、采集 ID 和原始 Index 可追溯。
4. 逐通道按可靠采样周期识别异常时间间隔。默认需要至少五个正间隔且至少四分之三位于中位数的一半至两倍，超过周期十倍时还要排除邻近稳定慢速采样。周期未知时只用明确的边界。Sysmac 可用索引缺号、通道空值和精确的周期采样时钟；重建时间不独立证明断采。全部通道缺口的共同时间区间才记为全通道缺口。记录中的连续长平台保留。
5. 按完整变量、起始步和结束步统计同一连续采样段内的跳变。采集首段和缺口后首段只计真实跳变次数。中位数、最大值和最小值仅使用有进入和离开样本的起始步。有效次数为零时三项留空。源码直跳、静态多步路径、经步 0 和无法解析的关系分别核查。静态路径仅用于解释观测。

6. 从实测跳变定位动作的实际判断、实例及写点。补列同一判断的其他出口及其内部步，核查汇合、独立动作与共享复位的边界。每条补录行关联实际采集和样本位置。仅有路径证据时保留端点时长，各组成步的时长留空。
   在「实测跳变」按源程序段和写点读完整数值路径。相邻采样可跨过多个梯级，多个写点也可产生同一数值出口。回到较早梯级、父程序写初值及跨动作调用仅解释端点来源。复核父子控制变量及调用位置，按采集保留端点次数和时长，将需要区分出口的运行条件列入复核。

## 验收

| 入口 | 核对文件 | 核对内容 |
| --- | --- | --- |
| 一 | `trace_action_branches.csv`、`trace_branch_evidence.json`、`trace_branch_events.csv` | 逐分支核查收录依据、写点、事件和工况。同变量内独立动作在获得实测锚点后收录 |
