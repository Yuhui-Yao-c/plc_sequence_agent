# PLC 逻辑图谱

## 输入与执行

使用用户指定的原始 XML 或 SMC2 工程和实测 Trace。Sysmac 可传整个分卷目录。对话简写为 `源码路径 Trace路径 --logic-graph [-output 输出根目录]`。从项目根目录调用等价的 `python plc_cli.py` 命令。以标准输出返回的实际交付目录为准。

## 整机协作分析

打开“协作总览”，在写入程序行与接收程序列的交点选择信号。需要查看整台设备的原始结构时，打开“整机图纸”，按任务挂载、程序、例程、网络定位。检查跨程序关系时写明完整信号地址、所有可能写入方、接收方及各端的 XML / ST 位置。对步序门控保留布尔条件和所有候选分支。打开“沿指令追踪上游和下游”，分别核对写入条件、赋值取数、块输出端口和实例。实测状态对的出现次数属于该状态对。确定实际触发支路还需本次采样的对应操作数。对功能块先核实例和形参方向，再进入定义。将已导出的接口边界和缺少运行时操作数的情况写入结论。

抽验一个展开网络的串并联、极性和端口，以及一条跨程序写读关系。对只读公共输入、动态地址、多个可能写入方及缺少声明的引用保留其证据等级。

## 步序分析

1. 在“步序与观测”选择完整变量地址和起止值。记录采集编号、样本索引、发生次数，查看全部直接写点。采样间隔可以跨过一个或多个源码步值。
2. 在源码写点核对程序、例程、XML 行、ST 相对行与实例实参。打开“门控图”检查 AND、OR、NOT 等层级，再打开“源码网络”查原始引脚、触点极性、分支、线圈、定时器及块输出。分析一条支路时保留其它可达分支。
3. 用“信号读写”沿操作数追查赋值和读点，核对声明作用域与下标。赋值位置和库块调用只证明可能的来源。只有记录在同次采集同一行或唯一匹配时间戳的操作数才可报告其采样值。读数对应观测到新状态的时刻，无法据此还原扫描内部先后。
4. 对多步候选逐段核查写点，标明中间状态的证据等级。对未对齐关系保留实测跳变，记录未解析的接线、间接写入、程序或实例。工程目录收录本次未采集的源码网络。

## 验收与交付

核对 `workflow_status.json` 的输入指纹和产物哈希。观测对数应等于直接写点、多步候选、未对齐三项之和，源码独有状态对另计。选一条有写点的观测边从 HTML 回查 XML，核对接线方向和输入端口；存在多步或待核项时各抽一条。交付 `logic_graph.html`，需要二次分析时附 `logic_graph.json.gz`。报告已解析范围、未对齐数、局部门控待解数及采样边界。依据本工程证据作解释，不以型号、工位编号、动作词表、人工监控赋值或其他工程的结果补边。
